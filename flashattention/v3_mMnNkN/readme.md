# FlashAttention

`flashattention/v3_mMnNkN` contains a CuTe/CUTLASS FlashAttention forward kernel and
the `flashatten_v3_sm120` Python extension. It is a fixed-shape, FP16 CUDA
implementation used for correctness checks and config benchmarking against
official `flash-attn`.

`v3_mMnNkN` means FlashAttention v3 with MMA EU layout `EU_QK(m=M,n=N,k=1)` and
`EU_PV(m=M,n=1,k=N)`.

## Features

- Forward attention only: `flashatten_v3_sm120.fwd(q, k, v, causal)`.
- Config-specific run: `flashatten_v3_sm120.fwd_config(config, q, k, v, causal)`.
- Supported inputs: CUDA, contiguous `torch.float16`, shape
  `[batch, seq_len, head_num, head_dim]`.
- Supported head dims generated by default: `64`, `128`.
- Supported head counts in the extension: `1`, `4`, `8`, `16`, `32`, `64`, `80`.
- Supported architecture: NVIDIA Blackwell `sm_120a` / `compute_120a` only.
- Reference implementation for validation: `flash_attn.flash_attn_func`.

## Requirements

- NVIDIA GPU and CUDA Toolkit with `sm_120a` support.
- CMake `>= 3.24`, Ninja, C++20/CUDA20 compiler support.
- Repository CUTLASS headers under `3rd/cutlass`.
- Python environment with `torch`, `pybind11`, and official `flash-attn`.

## Build

Run from the repository root. Replace `torch132` below with your own conda
environment that has `torch`, `pybind11`, and official `flash-attn` installed:

```bash
conda activate torch132
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export TORCH132_ENV="$CONDA_PREFIX"
export CUDA_HOME="${CUDA_HOME:-/usr/local/cuda}"
export PYBIND_BUILD="$REPO_ROOT/flashattention/v3_mMnNkN/pybind/build"
export LD_LIBRARY_PATH="$TORCH132_ENV/lib:${LD_LIBRARY_PATH:-}"

cmake -S "$REPO_ROOT/flashattention/v3_mMnNkN/pybind" -B "$PYBIND_BUILD" \
  -G Ninja \
  -DTORCH132_ENV="$TORCH132_ENV" \
  -DCMAKE_MAKE_PROGRAM="$TORCH132_ENV/bin/ninja" \
  -DCMAKE_BUILD_TYPE=Release

cmake --build "$PYBIND_BUILD" -j8
```

Optional build switches:

```bash
cmake -S "$REPO_ROOT/flashattention/v3_mMnNkN/pybind" -B "$PYBIND_BUILD" \
  -G Ninja \
  -DTORCH132_ENV="$TORCH132_ENV" \
  -DCMAKE_MAKE_PROGRAM="$TORCH132_ENV/bin/ninja" \
  -DCMAKE_BUILD_TYPE=Release \
  -DFLASH_FWD_MAX_SMEM_KB=100
```

`FLASH_FWD_MAX_SMEM_KB` filters generated configs by dynamic shared memory use.
To build only specific named configs, pass `FLASH_FWD_ONLY_CONFIGS` during
CMake configure and rebuild:

```bash
cmake -S "$REPO_ROOT/flashattention/v3_mMnNkN/pybind" -B "$PYBIND_BUILD" \
  -G Ninja \
  -DTORCH132_ENV="$TORCH132_ENV" \
  -DCMAKE_MAKE_PROGRAM="$TORCH132_ENV/bin/ninja" \
  -DCMAKE_BUILD_TYPE=Release \
  -DFLASH_FWD_ONLY_CONFIGS=hd64_bm64_bn64_wm4_wn2_s2

cmake --build "$PYBIND_BUILD" -j8
```

`FLASH_FWD_ONLY_CONFIGS` is useful for fast iteration because it skips all
default configs. Multiple config names can be separated with commas.

Generated config names use:

```text
hd<head_dim>_bm<block_m>_bn<block_n>_wm<warps_m>_wn<warps_n>_s<stage>
```

For example, `hd64_bm64_bn64_wm4_wn2_s2` means head dimension `64`, block M
`64`, block N `64`, `4` M-warps, `2` N-warps, and pipeline stage `2`.

Load the built extension from `pybind/build`:

python - <<'PY'
import sys

## Test One Kernel

`test.py` only launches the custom kernel selected by `--func`. It does not
compare against official `flash-attn`.

List all supported template config kernel functions:

```bash
cd "$REPO_ROOT/flashattention/v3_mMnNkN"
python test.py
```

Run one generated kernel config:

```bash
cd "$REPO_ROOT/flashattention/v3_mMnNkN"
python test.py \
  --config b2_hn8_seq256_hd64_casual1 \
  --func hd64_bm64_bn64_wm4_wn2_s2
```

`--config` is the input shape:

```text
b<batch>_hn<head_num>_seq<seq_len>_hd<head_dim>_casual<0|1>
```

It also accepts explicit dimensions:

```bash
python test.py --config 2048 64 16 1 true --func hd64_bm64_bn64_wm4_wn2_s2
```

`--func` is the generated function config name, for example
`hd64_bm64_bn64_wm4_wn2_s2`.

## Verify

Run all default correctness cases:

```bash
cd "$REPO_ROOT/flashattention/v3_mMnNkN"
python verify.py
```

This verifies every shape in `test_shapes` with both `causal=0` and `causal=1`,
using the default config selected by `flashatten_v3_sm120.fwd(...)`.

Run only `b1_hn1_seq64_hd64_casual1`:

```bash
cd "$REPO_ROOT/flashattention/v3_mMnNkN"
python verify.py --case 64 64 1 1 true
```

Run every instantiated kernel template config:

```bash
cd "$REPO_ROOT/flashattention/v3_mMnNkN"
python verify.py --all
```

`--all-configs` is kept as an alias for `--all`.

This mode verifies each unique kernel template instance exactly once:

```text
(config_name, HeadNum, Causal)
```

The number of kernel templates is:

```text
len(flashatten_v3_sm120.configs()) * 7 HeadNum values * 2 Causal values
```

`HeadNum` values are:

```text
1, 4, 8, 16, 32, 64, 80
```

`--all` cannot be combined with `--case`.

`verify.py` output format:

```text
PASS b1_hn1_seq64_hd64_casual1 max_abs=... max_rel=... mismatches=0/4096
PASS b1_hn1_seq64_hd64_casual1 hd64_bm64_bn64_wm4_wn2_s2 max_abs=... max_rel=... mismatches=0/4096
```

Fields:

- `PASS` / `FAIL` / `SKIP_RESOURCE`: verification status.
- `b1_hn1_seq64_hd64_casual1`: input shape and causal flag.
- `hd64_bm64_bn64_wm4_wn2_s2`: kernel template config, shown by `--all`.
- `max_abs`, `max_rel`: maximum absolute and relative error.
- `mismatches`: elements outside tolerance.

## Benchmark

Benchmark default shapes and write `flashattention/v3_mMnNkN/benchmark.txt`:

```bash
cd "$REPO_ROOT/flashattention/v3_mMnNkN"
python benchmark.py
```

Benchmark all shapes in both causal modes:

```bash
cd "$REPO_ROOT/flashattention/v3_mMnNkN"
python benchmark.py --all
```

Benchmark only `b1_hn1_seq64_hd64_casual1`:

```bash
cd "$REPO_ROOT/flashattention/v3_mMnNkN"
python benchmark.py --case 64 64 1 1 --causal true --warmup 10 --iterations 100
```

Benchmark one generated config:

```bash
cd "$REPO_ROOT/flashattention/v3_mMnNkN"
python benchmark.py \
  --config hd64_bm64_bn64_wm4_wn2_s2 \
  --case 64 64 1 1 \
  --causal true \
  --warmup 10 \
  --iterations 100
```

Standard output lists every runnable config:

```text
b1_hn1_seq64_hd64_casual1 hd64_bm64_bn64_wm4_wn2_s2 180.028M 0.022752
```

Format:

```text
<case_label> <config_name> <throughput> <avg_ms>
```

`benchmark.txt` keeps the best custom config per case and the official baseline:

```text
b1_hn1_seq64_hd64_casual1 hd64_bm64_bn64_wm4_wn2_s2: 180.028M 0.022752 official_flashatten2: 43.866M 0.093376 custom/official:410.41%
```

Format:

```text
<case_label> <best_config>: <custom_throughput> <custom_avg_ms> official_flashatten2: <official_throughput> <official_avg_ms> custom/official:<ratio>
```

`case_label` is always:

```text
b<batch>_hn<head_num>_seq<seq_len>_hd<head_dim>_casual<0|1>
```

For example, `b1_hn1_seq64_hd64_casual1` means batch `1`, head number `1`,
sequence length `64`, head dimension `64`, and causal mode enabled.

### Compute Throughput (ncu)

`test_compute_rate.py` launches exactly one `flashatten_v3_sm120.fwd_config`
kernel inside a `cudaProfilerStart` / `cudaProfilerStop` region (after a few
warmup launches), then sleeps. This isolates a single kernel so Nsight Compute
can profile only that launch.

List runnable configs:

```bash
cd "$REPO_ROOT/flashattention/v3_mMnNkN"
python test_compute_rate.py --list
```

Profile one config and capture the SM (compute) throughput:

```bash
cd "$REPO_ROOT/flashattention/v3_mMnNkN"
mkdir -p "$REPO_ROOT/tmp/ncu"
ncu --profile-from-start off -c 1 \
  --metrics sm__throughput.avg.pct_of_peak_sustained_elapsed,dram__throughput.avg.pct_of_peak_sustained_elapsed \
  -o "$REPO_ROOT/tmp/ncu/mMnNkN__b1_hn16_seq2048_hd64_casual1" -f \
  python test_compute_rate.py \
    --func hd64_bm64_bn64_wm4_wn2_s2 \
    --seq-len 2048 --head-num 16 --batch 1 --causal 1 \
    --warmup 3 --sleep 10
```

`--profile-from-start off` tells Nsight Compute to ignore the warmup launches
and profile only the kernel between `cudaProfilerStart` and `cudaProfilerStop`;
`-c 1` captures that single launch. Read the SM throughput back from the report
(the data row holds `sm__throughput.avg.pct_of_peak_sustained_elapsed`):

```bash
ncu -i "$REPO_ROOT/tmp/ncu/mMnNkN__b1_hn16_seq2048_hd64_casual1.ncu-rep" \
  --csv --page raw
```

`test_compute_rate.py` flags:

- `--func`: generated config name (required unless `--list` / `--list-names`).
- `--seq-len`, `--head-num`, `--batch`: input shape (`head_dim` comes from `--func`).
- `--causal`: `0` / `1`.
- `--warmup`: launches before profiling starts (default `1`).
- `--sleep`: seconds to sleep after the profiled launch (default `10`).
- `--list` / `--list-names`: print configs and exit.
